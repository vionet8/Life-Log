# ACTジャーナリング 設計メモ

Life-Log の機能⑤「ACTジャーナル」の背景・設計・実装対応表。

---

## 1. 背景：人生には燃料を切り替える時期がある

ロケットが燃料を切り離して次の段に乗り換えるように、人生にも動力源を切り替える時期がある。

### 第1弾の燃料（人生の前半）

承認欲求・自立・獲得・拡大（年収、昇進、結婚など）が動力源になる。
未来が不確実で可能性に満ちていると感じられるうちは、これらは強い報酬として機能する。

### ミドルエイジ・クライシスの正体

経験を積み、未来がある程度予測可能になると、第1弾の燃料に心が反応しなくなる
（＝攻略済みのゲームをしている状態）。

このとき多くの人が取る行動：

- さらなる成果を追う
- 環境を変える（転職・引っ越し・関係の作り直し）
- 自己分析を繰り返す

これらはしばしば、虚無感や不安という不快な感情を消そうとする
**「体験の回避」** の罠になっている。感情を消すことが目的化すると、
どれだけ動いても方向は決まらない。

### 第2弾の燃料（人生の後半）

「何を手に入れるか（目標）」ではなく、
**「どの方向へ、どのような態度で進むか（価値）」** を動力源にする。

目標は達成すると終わる。価値は終わらない——進み続けられる方向である。

### ACTによる処方箋

嫌な感情を消そうとするのではなく、**それらを抱えたまま、大切にしたい方向へ進む**。
この力を **心理的柔軟性** と呼ぶ。ACTジャーナルはそれを日々の習慣にするための道具。

## 2. 4ステップの設計

1回のジャーナルは4つの問いで構成する。各ステップはユーザーの入力1回で進む。

### ステップ1：アクセプタンス（今の状態を認める）

不快な感情を「消すべき敵」ではなく、単なる事実として観察する。

- **問い**：今、心の中にどのような「名前のない不安」「虚しさ」「痛み」があるか
- **書き方**：「私は〜と感じている」と、実況見分するように書く。
  解決しようとせず、いったん「ポケットに入れる」感覚で認める

### ステップ2：体験の回避チェック（行動の動機を探る）

今の行動が「逃げ」か「攻め」かを確認する。

- **問い**：最近の行動は「避けたいもの（失敗・暇・無価値感）」から離れるためか、
  それとも「大切なもの」に近づくためか
- **書き方**：「〜と思われたくないから働く」のか「〜を作りたいから働く」のか、
  動機の違いを言語化する
- **重要**：回避だと分かっても責めない。気づけたこと自体を事実として置く

### ステップ3：価値の明確化（第2弾の燃料を確認する）

目標（達成して終わるもの）ではなく、価値（進み続ける方向）を再定義する。

- **問い**：今、目の前の仕事や人間関係に、どのような「態度」で関わりたいか
- **例**：誠実でありたい／好奇心を持ちたい／次世代に手渡したい／自分を丁寧に扱いたい

### ステップ4：コミット型のアクション（1cmの行動）

大きな変化ではなく、今日選べる最小の行動を決める。

- **問い**：設定した価値の方向に1cmだけ近づくとしたら、今この瞬間（あるいは今日）何を選ぶか
- **例**：家族に短い連絡を入れる／引き受けたくない依頼を1つ断る／
  完成させなくていいから3割だけ手をつける

## 3. 運用の原則

- **行動を重視する** — ACT（アクト）はその名の通り「行動」を最重視する。
  深く考えることよりも、日常の中で繰り返し方向を確認し、小さく体現し続けることが重要。
- **痛みを引き受ける** — 大切なものへ近づく行動には、しばしば痛みが伴う（挑戦による失敗の可能性など）。
  その痛みも含めて主体的に引き受ける「生き方の選択」としてジャーナリングを使う。
- **習慣化のループ** — 次回のジャーナル開始時に、前回の1cmの行動がどうなったかを必ず確認する。
  できていなくても責めない。実行できたかどうかより、方向を選び直し続けることが本体。

### AIが絶対にやらないこと

3つのペルソナ（ユウ／ナギ／ミライ）は口調が違っても、以下は共通で守る。

| 禁止 | 理由 |
|------|------|
| 「大丈夫」「きっとうまくいく」等の慰め・保証 | 感情を消す方向に働き、アクセプタンスを壊す |
| 「〜すべき」「〜した方がいい」という助言・解決策 | 価値は本人が決めるもの。AIが方向を与えない |
| 「それは不安ですね」等の感情のラベリング・診断 | 観察を奪う。本人の言葉のままで扱う |
| 「すごい」「立派」等の評価 | 承認＝第1弾の燃料を再供給してしまう |
| 体験の回避を責める | 回避に気づけたこと自体が前進のため |

## 4. 実装対応表

### 状態遷移（`backend/handlers/act.py`）

```
idle → act_prev    … 前回の1cmの行動の結果確認（未確認ログがある場合のみ）
     → act_accept  … ステップ1 アクセプタンス
     → act_avoid   … ステップ2 体験の回避チェック
     → act_value   … ステップ3 価値の明確化
     → act_action  … ステップ4 コミット型アクション
     → act_confirm … 1cmの行動をタスクに追加するか / 取り消し
     → idle
```

補助動作：

- ステップ3の選択肢には、過去に選んだ価値を優先して並べる（続けるほど自分の言葉に寄る）
- ステップ4で「💡 思いつかない」を選ぶと、価値に沿った最小の行動を3つ提案する
  （感情を晴らすための行動＝体験の回避は提案しない）
- ステップ4のあと「✅ タスクに追加」を選ぶと、1cmの行動がタスクリストに入る

### 起動方法

リッチメニュー（2×3＝6枠）は既に埋まっているため、テキストで起動する。

- キーワード：`ACTジャーナル` / `🧭 ACTジャーナル` / `アクトジャーナル` / `ACT`
- idle 状態でメニュー外のメッセージを送ったときのクイックリプライにも表示される
- 「ヘルプ」の使い方案内にも記載

### データ（`backend/models/database.py`）

`act_logs` テーブル：

| 列 | 内容 |
|----|------|
| `acceptance` | ステップ1 いま在る感情 |
| `avoidance` | ステップ2 行動の動機 |
| `value_text` | ステップ3 価値（進みたい方向） |
| `action` | ステップ4 1cmの行動 |
| `action_done` | 0=未確認 / 1=やった / 2=やらなかった・変えた |
| `entry_id` | 対応する `entries` 行への参照 |

同時に `entries` にも `entry_type='act'` の行を書き、振り返りレポートから読めるようにする。

### 振り返りへの反映

- `review_stats.compute_act_stats()` が決定論的に集計する
  （価値の登場回数／動機の内訳／1cmの行動の実行率）。
  実行率の分母は「結果を確認済みの行動」だけ——未確認は成否不明なので数えない。
- `claude_service.generate_review()` は、ACT記録がある期間だけ
  「🧭 価値と1cmの行動」セクションを追加する。
- 数値は既存方針どおり Python 側で確定させ、Claude には解釈だけを任せる。

### テスト

```
python -m scripts.test_act_flow
```
